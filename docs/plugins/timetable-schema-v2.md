## 2. 数据层次

| 字段 | 是什么 | 关键约束 |
| --- | --- | --- |
| `schemaVersion` / `id` / `mode` | 文件合同、课表稳定ID、demo或personal用途 | v2严格拒绝未知字段；ID不能靠课程名称猜测 |
| `semester` | 日期显示范围、时区及学校周次映射 | startDate为显示周起点（星期一），不自动等同开学日；weeks是显示周数；weekNumberStart可为null |
| `periods` | 学校作息节次表 | id、start/end及作息来源；时间合法、不重叠；并非每节都要有课 |
| `courses` | 一门课程的身份 | id、课程编号code、名称name；不把教师/教室固定在课程上 |
| `sections` | 课程的班级 | id、courseId、班级名；同课不同班不混为一门已选班级 |
| `meetings` | 一个班级的一次上课时段 | id、sectionId、绝对日期date、dayPart、time、room、teachers、source、rawEntries、notes |
| `meetings.time` | 实际或参考的节次范围及依据 | periodIds连续；status为confirmed/reference/unknown；unknown必须空节次，其余必须非空 |
| `teachers` / `rawEntries` | 本次教师与原始记录 | null保留未注明教师；同格两条教师原文完整保留，不无证据拆成两个并发课程 |
| `sources` / `source` | 来源文件及定位 | 文件标题、SHA-256；字段来源定位到表格行/星期或Excel单元格。哈希用于追溯，不等同来源可信性认证 |
| `reminders` | 提醒开关和提前分钟数 | demo必须enabled=false；personal启用前所有会议时间必须confirmed；仍限每次最近32条计划 |

课程→班级→授课为一对多关系。`meeting.id`是持久身份，初次生成可以包含来源日期，但之后调整日期不要求重建ID。老师更换或地点变化应修改对应授课，而不是伪造新课程。相同班级/日期/时段/节次的重复授课拒绝导入，应先核实并合并教师记录。

v2以绝对日期保存最终课表，不同时维护另一份可冲突的周次递推规则。源文件的单双周/区间可在导入时展开为日期并保留原文；当前打印表已有日期，不需要借旧周次反推。既有v1重复周次仍由原codec解释。

## 4. 校验和提醒门禁

结构层由schema约束字段类型、枚举、数组和文本上限、必填项及额外字段。应用接收上限仍为256KiB。语义层追加真实日历日期、显示范围、唯一ID、课程/班级/来源外键、连续节次、作息不重叠、重复授课及demo提醒禁用。

reference只是参考，不是confirmed；unknown可保存并显示“时间未确定”，不伪造钟点。提醒关闭时允许保留不确定信息；personal申请启用提醒但存在未确认时间时，计划生成失败并说明原因，不悄悄生成部分计划。用户确认时间后才可生成个人提醒。demo无论日期是否在未来均返回空计划。

schema v2的当前边界不包含学分审核、成绩、选课提交、考勤及调停课历史流水；课程取消可在经确认的整表替换中移除，其历史记录机制另行版本化，不用未实现字段冒充已支持功能。
