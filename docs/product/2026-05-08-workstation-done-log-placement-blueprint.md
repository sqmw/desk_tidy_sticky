# 工作台里“记录做了什么”应该放在哪：信息架构蓝图（2026-05-08）

## 1. 结论

如果要把“当前记录做了什么 / 已办记录 / Done Log”做进 `workstation（工作台）`，**最推荐的放置方案不是“把统计单独拎出来作为一个 tab”**，而是：

- 新增一个一级 tab：`回顾`
- 将 `已办记录 + 日历 + 统计` 统一收在 `回顾` 里
- `专注` 页面只保留运行控制、任务规划和少量统计摘要，不再继续承担完整复盘职责

一句话：

> `统计` 不是这个新能力的主语，`回顾` 才是。  
> “记录做了什么” 和 “统计做成了多少” 本质上都属于回顾层。

---

## 2. 当前现状

## 2.1 当前工作台一级结构

当前 `workstation` 只有两个一级 tab：

- `笔记`
- `专注`

对应代码：

- `src/lib/workspace/workspace-tabs.js`

当前定义：

- `WORKSPACE_MAIN_TAB_NOTES = "notes"`
- `WORKSPACE_MAIN_TAB_FOCUS = "focus"`

## 2.2 当前“统计”所在位置

现在的 `统计` 不是一级 tab，而是 `专注` 里的**底部可折叠统计面板**。

对应实现：

- `src/lib/components/workspace/WorkspaceFocusHubView.svelte`
- `src/lib/components/workspace/pomodoro/WorkspaceFocusStats.svelte`

当前行为：

1. 用户进入 `专注`
2. 看到计时卡 + 任务规划
3. 底部点开 `统计`
4. 查看今日专注、热力图、任务分布等信息

这套设计在“专注统计只服务专注”时是成立的，但如果你再加入：

- 当前记录做了什么
- 已办记录
- 日历回看
- 生活/工作轨迹

那这套放置方式就开始不顺了。

---

## 3. 这次新功能的本质是什么

“记录做了什么”这个能力，本质上不是：

- 任务规划
- 番茄控制
- 运行时设置

它更像是一个**结果层 / 回顾层**，回答的是：

1. 今天做成了什么
2. 什么时候做成的
3. 当时有什么想法
4. 这一周/这一月是怎样的轨迹
5. 专注时间和真实产出能不能对上

所以它天然更接近：

- `回顾`
- `日志`
- `复盘`
- `统计`

而不是 `专注` 本身。

---

## 4. 候选放置方案对比

## 方案 A：把“统计”单独拎成一级 tab，并把新功能塞进去

### 结构

- 笔记
- 专注
- 统计

然后在 `统计` 里放：

- 已办记录
- 日历
- 专注数据

### 优点

1. 入口数量少，容易实现。
2. 现有 `专注 -> 统计` 可以整体迁过去。
3. 技术迁移成本相对低。

### 问题

1. `统计` 这个名字太窄了。
2. 用户会默认认为：
   - 这里只看图表/数字
   - “记录做了什么”只是统计附属物
3. 已办记录、日历回看其实是内容型浏览，不是纯统计。
4. 长期看会形成奇怪体验：
   - 用户想写一条“今天完成了什么”
   - 却得进一个叫“统计”的地方

### 结论

不推荐作为最终方案。  
它更像工程迁移命名，不像产品命名。

---

## 方案 B：把“记录做了什么”放在 `笔记` 里，做成一个新视图

### 结构

- 笔记
  - 活动
  - 已归档
  - 回收站
  - 已办记录
  - 日历
- 专注

### 优点

1. 不增加一级 tab。
2. 数据层可直接复用 `note`。
3. “记录”与现有 note 心智接近。

### 问题

1. `笔记` 是输入态主场。
2. `已办记录 / 日历 / 回看` 是结果态主场。
3. 两者混在一起，用户会分不清：
   - 普通笔记
   - 归档笔记
   - 已办记录
   - 回顾日历
4. 如果把统计也放进笔记区，就更乱。

### 结论

可作为**极简过渡方案**，但不适合作为长期 IA。

---

## 方案 C：新增一级 tab `回顾`，把“记录 + 日历 + 统计”统一收口

### 结构

- 笔记
- 专注
- 回顾

其中 `回顾` 下再分为：

- 已办
- 日历
- 统计

### 优点

1. 名称上更准确。
2. “记录做了什么”和“统计做成多少”天然同类。
3. 可以把现在 `专注` 页里不断膨胀的统计内容迁出来，减轻 `专注` 页面负担。
4. 长期可扩展：
   - On This Day
   - 周报/月报
   - 已办趋势
   - 专注与产出对照

### 风险

1. 一级 tab 从 2 个变 3 个，工作台复杂度上升。
2. 如果 `回顾` 内容太少，会显得 tab 很空。

### 为什么仍然推荐

因为它的语义最干净，而且能反过来**收缩**现在的 `专注` 页面。

也就是说：

- 新增一个 tab
- 但减少一个页面的职责堆积

这是“加结构换清晰度”，不是单纯继续加功能。

### 结论

**推荐方案**

---

## 5. 推荐的信息架构

## 5.1 一级 tab

推荐工作台一级 tab 改为：

- `笔记`
- `专注`
- `回顾`

### 笔记

负责：

- 随手记
- 草稿
- 长文内容编辑
- 标签整理
- 归档 / 回收站

关键词：

- `输入`
- `整理`
- `沉淀内容`

### 专注

负责：

- 番茄运行
- 任务规划
- 任务启动 / 暂停 / 继续
- 休息控制

关键词：

- `运行态`
- `执行`
- `节奏控制`

### 回顾

负责：

- 当前记录做了什么
- 已办记录
- 日历视图
- 统计图表
- 历史轨迹

关键词：

- `结果`
- `回看`
- `复盘`

---

## 5.2 回顾 tab 内部二级结构

推荐 `回顾` 下分 3 个视图：

- `记录`
- `日历`
- `统计`

### 记录

展示：

- 时间线列表
- 每条已办记录
- 标题 / 时间 / 标签 / 摘要 / 图片

这是“我做了什么”的主场。

### 日历

展示：

- 月历
- 每日完成情况
- 点击某天看详情

这是“哪天做了什么”的主场。

### 统计

展示：

- 今日 / 本周 / 本月专注时长
- 已办数量趋势
- 专注和产出关系
- 任务 / 类型分布

这是“做成了多少、做成得怎么样”的主场。

---

## 6. 为什么“统计单独一级 tab”不如“回顾一级 tab”

这个点是本轮最关键判断。

## 6.1 用户意图不同

当用户想：

- 看一条自己做完的记录
- 补记一张图片
- 回想昨天干了什么

他脑子里想的是：

- 回顾
- 看记录
- 看日历

不是：

- 去统计页

## 6.2 内容密度不同

`统计` 更适合承载：

- 数字
- 图表
- summary

而 `记录做了什么` 更适合承载：

- 列表
- 时间线
- 图片
- 长文本感想

这两种内容同属回顾层，但不应该被“统计”这个窄名词统摄。

## 6.3 长期扩展时更自然

如果未来你要加：

- 本周回顾
- 本月精选
- On This Day
- 任务完成轨迹

这些都更自然地挂在 `回顾` 下，而不是 `统计` 下。

---

## 7. 当前统计应该怎么处理

## 7.1 不建议完全删掉专注页里的统计痕迹

虽然完整统计应迁到 `回顾`，但 `专注` 页面仍然需要保留少量摘要，否则用户会失去运行反馈。

建议保留：

- 今日专注分钟
- 今日番茄总数
- 连续专注天数
- 一个“查看完整回顾”入口

## 7.2 推荐迁移后的专注页形态

### 保留在专注页的

- 顶部当前任务与计时
- 任务规划
- 休息控制
- 一行或一块轻量 summary

### 迁出到回顾页的

- 热力图
- 今日任务分布时间线
- 历史任务 rollups
- 周 / 月统计图表
- Done Log 时间线与日历

这样做以后，专注页会更像：

- 控制台

回顾页会更像：

- 成果板 / 复盘台

---

## 8. 推荐交互草图

## 8.1 一级 tab

- 笔记
- 专注
- 回顾

## 8.2 回顾页顶部摘要

建议回顾页顶部先有一条 summary bar：

- 今日专注：`120m`
- 今日已办：`3 条`
- 本周已办：`12 条`
- 连续记录：`5 天`

这样用户一进来就知道这里不是空页面，而是“我最近做了什么”的总览。

## 8.3 回顾页二级切换

- `记录`
- `日历`
- `统计`

默认推荐落在：

- `记录`

因为这是最贴近“我今天到底做了什么”的直接答案。

---

## 9. 实施顺序建议

## Phase 1：先完成 IA 收口

只做结构迁移，不急着做全部功能：

1. 新增一级 tab：`回顾`
2. 把 `专注` 页完整统计迁到 `回顾 -> 统计`
3. `专注` 页保留轻量 summary

这样即使还没做 Done Log，结构也已经顺了。

## Phase 2：接入已办记录

1. `回顾 -> 已办`
2. `回顾 -> 日历`
3. `补记已办` 创建入口（入口轻量，编辑卡插入时间线内）
4. 基于 `completed_at` 聚合

## Phase 3：闭环强化

1. 从专注任务生成已办
2. 周 / 月回顾
3. `On This Day`

---

## 10. 如果想更保守，有一个过渡方案

如果你担心现在直接加 `回顾` tab 太早，可以先走过渡态：

- 一级 tab 仍然保持：
  - 笔记
  - 专注
- 但把原先 `专注` 底部的 `统计` 改名为：
  - `回顾`
  或
  - `复盘`

然后里面先放：

- 统计
- 已办记录入口

等内容成熟后，再把它真正提升为一级 tab。

这个过渡方案比“直接做统计一级 tab”更合理，因为它从命名上已经在向正确方向靠近。

---

## 11. 最终建议

### 最推荐方案

- 工作台新增一级 tab：`回顾`
- `回顾` 下包含：
  - `记录`
  - `日历`
  - `统计`

### 为什么不是“统计单独一级 tab”

因为：

1. `统计` 语义太窄
2. 无法自然承载“记录做了什么”
3. 容易把内容型回顾误导成图表附属物

### 为什么不是继续塞在 `专注`

因为：

1. `专注` 是运行态
2. `记录做了什么` 是结果态
3. 二者混在一起，会继续推高页面复杂度

### 为什么不是长期放在 `笔记`

因为：

1. `笔记` 偏输入与编辑
2. `已办记录` 偏回顾与结果
3. 长期会把“笔记”和“已办”搅在一起

---

## 12. 一句话版本

如果只是为了不让工作台继续膨胀，最偷懒的做法是把统计单独拎成 tab。  
但如果从长期产品心智看，**更对的方案是新增一个 `回顾` tab，把“当前记录做了什么”与“统计”都收进去。**
