# 工作台笔记概念统一：移除“写长文档”并列入口（2026-04-27）

## 背景

- 工作台顶部原先同时提供两个入口：
  - `新建笔记`
  - `写长文档`
- 但从数据层和持久化层看，两者底层都创建同一种 `note`。
- 区别只在于：
  - `新建笔记`：快速创建后留在列表
  - `写长文档`：创建后直接进入右侧 inspector 编辑

这会带来明显的产品心智问题：

1. 用户会误以为“笔记”和“长文档”是两种对象。
2. UI 上出现双入口，但底层并没有双模型。
3. 文案、代码命名和文档长期分叉，持续增加理解成本。

## 决策

- 对外统一为一个概念：`笔记`
- 工作台顶部只保留一个主入口：`新建笔记`
- “长文档”不再作为并列对象类型存在
- 需要大编辑器时，视为“笔记的编辑路径”，而不是另一种内容类型

## 当前行为

工作台顶部创建栏现在采用单一动作：

1. 如果输入框已有内容：
   - 点击 `新建笔记`
   - 或在输入框里按 Enter
   - 直接创建笔记
2. 如果输入框为空：
   - 点击 `新建笔记`
   - 创建一条空白笔记草稿
   - 立即进入右侧 inspector 编辑态

默认空白模板：

- zh: `# 新笔记`
- en: `# New note`

## 实现收敛

### UI

- 删除工作台顶部 `写长文档` 次按钮
- 保留单一主按钮 `新建笔记`
- 更新输入框提示文案，明确：
  - 可输入内容后回车快速创建
  - 也可直接新建空白笔记
- `新建笔记` 按钮增加 `+` 图标，并调轻底色与阴影，保持主入口身份但避免视觉过重

## 2026-04-27 补充：创建区交互语义

- 左侧输入框：`快记`
  - 输入内容后按 Enter，立即创建一条笔记
- 右侧 `+ 新建笔记`：`空白起稿`
  - 当输入框为空时，创建空白笔记并直接进入右侧编辑器

这样可以把两个行为明确区分为：

1. 已经想好内容时，快速落一条
2. 想认真起稿时，从空白笔记进入编辑

### 控制器

- `createLongDocument()` 收敛为统一创建动作
- `pendingLongDocDraft` 收敛为 `pendingEditorDraft`
- inspector 临时草稿删除逻辑继续保留：
  - 空白草稿若直接取消，不保留脏数据

### 对外文案

- README / contributing 不再把 `long documents / 长文档` 作为当前并列能力描述
- 统一描述为：
  - `notes + editor workflow`
  - `笔记 + 右侧编辑`

## 影响

### 正向

- 产品概念更干净
- UI 入口减少，理解成本更低
- 代码命名与真实模型对齐

### 兼容

- 右侧 inspector 编辑能力保留
- 历史文档中对“长文档”的记录保留为历史决策，不影响当前实现

## 验证建议

1. 在 workstation 输入内容后按 Enter，应直接创建笔记。
2. 清空输入框后点击 `新建笔记`，应创建空白笔记并进入右侧编辑态。
3. 对这条空白草稿点击取消，应按现有临时草稿逻辑删除，不保留空记录。
