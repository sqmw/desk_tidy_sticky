# 已办记录 / Done Log 蓝图（2026-05-05）

## 1. 结论

这个方向值得做，但不建议把它做成一个与当前 `笔记` 并列的新大对象，也不建议一上来做成“重 journaling App”。

更优落点是：

- 在当前 `note` 基础上新增一层 `已办记录 / Done Log` 语义。
- 以 `workstation（工作台）` 为主入口，增加 `日历 + 时间线 + 已办回看`。
- mini 模式保留 `快速记一条`，但允许用户一键把当前记录归入 `已办`。

一句话定义：

> Desk Tidy Sticky 不是再做一个待办工具，而是在现有桌面便笺与工作台之上，补一个“今天我到底做成了什么”的回看层。

---

## 2. 为什么值得做

### 2.1 用户问题真实存在

当前主流效率工具大都围绕 `待办 / 截止时间 / 计划未来` 展开，用户容易出现两个问题：

1. 总感觉被未来事项追着跑。
2. 一天很忙，但回头看时没有“已完成”的证据沉淀。

`已办记录` 正好补的是这个空位：

- 降低待办压力感。
- 强化完成感与回顾价值。
- 让“记录”从纯输入，变成“进展可见”。

### 2.2 市场侧并非空白，但仍有切入口

调研到的相邻产品主要分三类：

#### A. done list / 团队进展记录

- `iDoneThis`
- 核心点：
  - 记录每日完成事项
  - 自动提醒填写
  - 可回看历史
  - 支持日历与汇总

官方页面强调：

- 记录 daily achievements
- automatic prompts
- searchable history
- calendar view

来源：

- [iDoneThis How it Works](https://www.idonethis.com/how-it-works)

#### B. 日记 / 回忆型产品

- `Day One`
- 核心点：
  - 日历视图
  - 照片 / 视频 / 地点 / 元数据
  - `On This Day`
  - 强调“回看人生轨迹”

官方页面强调：

- calendar view
- navigate entries by date
- on this day
- photos & videos & locations

来源：

- [Day One Calendar View](https://dayoneapp.com/features/calendar-view/)

#### C. 低负担日历记录

- `DailyBean`
- 核心点：
  - 几次点击完成记录
  - 月历总览
  - 一张图 + 一行文字
  - 分类可裁剪

官方页面强调：

- record in seconds
- customizable blocks
- pattern analysis
- daily logging should be easy

来源：

- [DailyBean App Store 页面](https://apps.apple.com/gb/app/dailybean-simplest-journal/id1553223828)

### 2.3 对当前项目的差异化机会

你这个项目不是从空白开始，而是已经有：

- 桌面便笺
- mini 快速记录
- workstation 工作台
- 标签 / 搜索 / 归档 / 回收站
- 图片粘贴与 Markdown 编辑
- 专注任务与番茄计时

这意味着你的切入点不是“做一个更像 Day One 的日志 App”，而是：

> 做一个更贴近桌面工作流的 `已办记录 + 工作回看 + 生活轨迹` 工具。

差异化重点：

1. 先记录，再整理。
2. 桌面悬浮与全屏场景里也能随手记。
3. 工作记录、灵感、完成事项、专注任务能互相串起来。
4. 回看维度更偏“今天做成了什么”，而不是纯情绪日记。

## 3. 不建议直接做成什么

为了避免范围失控，先明确不建议路线。

### 3.1 不建议做成独立的新对象体系

不建议上来就新增一套完全独立的：

- `done_entry`
- 独立编辑器
- 独立搜索
- 独立标签
- 独立图片资产流

原因：

1. 当前 `note` 已经具备大部分基础字段与编辑链路。
2. 双模型会立刻带来：
  - 新建入口冲突
  - 搜索冲突
  - 标签体系重复
  - 归档/回收站语义分裂
3. 当前项目的最大优势是“统一桌面记录入口”，不是“对象种类很多”。

### 3.2 不建议直接做成泛生活 journaling App

如果目标变成：

- 情绪追踪
- 健康追踪
- 地理轨迹
- 习惯统计
- 连续打卡社交分享

那会直接进入 `Day One / Daylio / DailyBean` 的成熟赛道，且会稀释你现有的桌面效率定位。

更合适的是：

- 以 `完成记录` 为核心
- 允许生活化内容进入
- 但不要把产品主心骨切成“万能日记”

## 4. 与当前架构的结合方式

## 4.1 当前已有可复用能力

从现有代码和数据结构看，`note` 已具备：

- 文本内容
- `created_at / updated_at`
- `tags`
- `is_done`
- `is_archived / is_deleted`
- 本地图片资产能力
- 搜索能力
- mini / workstation 双入口

这意味着 Done Log 的第一阶段完全可以复用当前对象。

## 4.2 推荐的语义映射

推荐增加的是“视图语义”，不是“底层双模型”：

- `note`
  - 仍然是唯一内容对象
- `record_kind`
  - 新增可选语义字段，建议值：
    - `note`
    - `done_log`
    - 未来如有必要再扩展

如果第一版想更保守，甚至可以先不改底层结构，只靠：

- `is_done`
- 特定 tag（如 `done` / `log`）
- UI 创建入口

来验证需求。

但从长期看，更推荐显式增加：

- `record_kind: "note" | "done_log"`
- `completed_at: string | null`

理由：

1. `is_done` 表示的是流程状态，不等于“这是一条已办记录”。
2. `created_at` 是创建时间，不等于真实完成时间。
3. `completed_at` 才能支撑日历、回看、统计、按天聚合。

## 5. 产品蓝图

## 5.1 核心对象

### Done Log 条目建议字段

在 `note` 复用前提下，建议最终语义补足为：

- `id`
- `record_kind`
- `title`
  - 第一版可由首行 / 第一标题推导
- `text`
- `completed_at`
- `created_at`
- `updated_at`
- `tags`
- `cover_image`
  - 第一版可由正文第一张图推导
- `source`
  - 可选：`manual` / `from_focus_task` / `from_note`

### 时间语义

这里最关键的是把三种时间分开：

1. `created_at`
   - 什么时候创建了这条内容
2. `updated_at`
   - 什么时候最后编辑
3. `completed_at`
   - 这件事真正完成于何时

Done Log 真正用于日历聚合的应该是 `completed_at`。

## 5.2 主入口设计

### 入口 A：workstation 新建已办记录

建议在工作台笔记区新增一个低冲突入口：

- `新建笔记`
- `记录已办`

但要注意概念不分叉：

- `新建笔记`：偏随记 / 草稿 / 想法
- `记录已办`：偏完成事项 / 回顾

如果你担心按钮过多，更优方案是：

- 单主按钮 `+ 新建`
- 下拉二级：
  - 笔记
  - 已办记录

### 入口 B：mini 模式快速落一条

mini 很适合这个方向，因为“已办记录”本质上也是轻输入：

- 输入一句“今天搞定了 Windows 图标层级 bug”
- 一键记为 `已办`

所以 mini 里可新增一个轻量动作：

- `保存为已办`

### 入口 C：从专注任务生成

这个是你项目独有价值点，建议作为第二阶段：

- 当一个 focus task 完成时：
  - 弹出“记一条已办记录”
  - 自动带入任务标题、番茄数、时间范围

这能把“专注”与“回看”真正串起来。

## 5.3 工作台视图蓝图

推荐把 Done Log 放在 workstation 中，作为 `笔记` 区域的一种视图，而不是再开一个完全独立的大页面。

### 方案

在 workstation 笔记区域增加视图切换：

- 活动
- 已归档
- 回收站
- 已办记录
- 日历

更收敛的方案则是：

- 左侧筛选：
  - 全部
  - 笔记
  - 已办
- 右上视图：
  - 列表
  - 日历

我更推荐第二种，因为它不会把信息架构拉得太散。

## 5.4 日历视图蓝图

### 月历是第一优先级

先做月历，不要一开始做周历/热力图/时间轴全家桶。

月历单元格里显示：

- 当天已办数量
- 1 张代表图或 1~2 个标题摘要
- 点击进入当天详情抽屉

### 当天详情抽屉

点击某天后显示：

- 日期
- 当天已办总数
- 按时间排序的记录列表
- 每条记录包含：
  - 标题
  - 完成时间
  - 一段摘要
  - 图片缩略图
  - 标签

### On This Day 值得做，但不是第一版

这个能力很强，但建议放第二阶段：

- 今天回看过去几年同一天做过什么

它适合作为产品记忆点，但不是验证需求的最小必需。

## 6. 第一版最小可行方案（推荐）

## 6.1 第一版目标

只验证三件事：

1. 用户愿不愿意记录“已办”
2. 日历回看是否带来成就感
3. 是否能与现有便笺/专注链路形成闭环

## 6.2 第一版范围

### 数据层

- 在 `note` 上补：
  - `record_kind`
  - `completed_at`

### 创建

- workstation 支持：
  - `新建笔记`
  - `记录已办`
- mini 支持：
  - `保存为已办`

### 展示

- 列表筛选：
  - `全部 / 笔记 / 已办`
- 日历视图：
  - 只展示 `done_log`
- 某天详情面板

### 编辑

- 标题
- 完成时间
- 正文感想
- 图片
- 标签

### 搜索

- 支持按标题 / 正文 / 标签搜索已办记录
- 搜索结果优先：
  - 标题命中
  - 正文命中
  - 标签命中

## 6.3 第一版暂时不做

- 社区/分享
- 心情打分
- 地图轨迹
- 自动 AI 复盘报告
- 多照片画廊复杂布局
- 复杂统计看板
- 单独移动端产品化

## 7. 推荐交互草图

## 7.1 创建

### workstation 顶部创建区

- 输入框 placeholder：
  - `记录今天完成了什么…`
- 主按钮：
  - `+ 新建笔记`
- 次按钮或下拉项：
  - `记录已办`

### 已办编辑面板

字段顺序建议：

1. 标题
2. 完成时间
3. 标签
4. 图片
5. 正文 / 感想 / 复盘

重点是：

- 时间要显式可编辑
- 不要只用创建时间偷渡

## 7.2 日历

推荐视觉语义：

- 空白日期：浅色底
- 有记录日期：轻高亮
- 多记录日期：角标数量
- 有图片日期：单图封面优先

点击日期后不是整页跳转，而是：

- 右侧 inspector
  或
- 底部抽屉

这样更贴近你当前 workstation 的信息架构。

## 8. 为什么这个方向适合当前项目

## 8.1 与桌面便笺天然顺手

很多 done list 产品的问题是：录入入口并不顺手。  
你这里恰好反过来：

- mini 面板
- 贴纸
- 全屏场景悬浮记录

都非常适合“事情做完，顺手记一下”。

## 8.2 与专注模块可形成闭环

当前项目已经有：

- focus task
- pomodoro
- break control

但缺少一个“结果层”。  
Done Log 正好补成闭环：

- 计划了什么
- 专注了多久
- 最后做成了什么

## 8.3 与现有笔记模型耦合成本低

当前 `note` 已有：

- 文本
- 时间
- 标签
- 图片
- 搜索
- 归档

所以第一版不需要大规模重造存储层。

## 9. 风险与代价

## 9.1 最大风险：概念混乱

如果入口和文案不收敛，用户会分不清：

- 普通笔记
- 已办记录
- 已完成待办

所以一定要明确：

- `已办记录` 不是“把待办打勾”
- 它是“回头记录已经发生的完成事实”

## 9.2 第二风险：工作台继续膨胀

当前 workstation 已经承担：

- 笔记
- 任务
- 番茄
- 休息

再加 Done Log，如果页面布局不收敛，很容易继续膨胀。

所以推荐：

- 复用现有笔记区域
- 新增筛选与日历视图
- 不再新开一整套平行系统

## 9.3 第三风险：图片能力可能推动范围升级

一旦允许图片，用户很快会期待：

- 拖拽上传
- 多图排序
- 封面选择
- 缩略图网格

所以第一版应限定为：

- 支持单图封面即可
- 多图仍留在正文 Markdown 中

## 10. 推荐路线

## 10.1 建议结论

建议做，但按两阶段推进。

### Phase 1：验证型实现

- `record_kind`
- `completed_at`
- 已办创建入口
- 已办列表筛选
- 月历视图
- 当天详情

目标：验证用户是否真的愿意持续记“已办”。

### Phase 2：形成产品记忆点

- 从 focus task 一键生成已办
- `On This Day`
- 周/月回顾
- 自动总结提示词
- 更好的图片封面与分享卡片

目标：从“能记”升级为“值得回看”。

---

## 11. 最终判断

### 值不值得实现

值得。

### 但应该怎么实现

不是做一个新的泛日记产品，而是：

- 以现有 `note` 为底
- 在 `workstation` 里补上 `已办记录 + 日历回看`
- 把它做成 `桌面记录工作流的结果层`

### 最适合当前项目的产品句子

> 先用 Desk Tidy Sticky 随手记、贴在桌面、进入专注；再用已办记录把今天真正做成的事情沉淀下来。

---

## 12. 后续若要开工，建议实现顺序

1. 数据层补 `record_kind / completed_at`
2. workstation 列表增加 `笔记 / 已办` 筛选
3. `记录已办` 创建入口
4. 月历视图
5. 当天详情面板
6. mini `保存为已办`
7. focus task -> done log 自动带入
