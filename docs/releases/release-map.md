## 维护规则

- 每次准备正式 release 时，先新增或更新对应版本行。
- 版本提交完成后，必须把 `Commit` 从“待回填”改成实际 commit、tag，或明确写成 tag 指向的提交。
- 如果 GitHub Release 使用 tag，优先记录 release tag；查询时用 `git rev-parse <tag>^{commit}` 获取实际 commit。
- 版本说明只写核心变化，详细实现记录放到 `docs/issues/`、`docs/ui/` 或专题文档。
