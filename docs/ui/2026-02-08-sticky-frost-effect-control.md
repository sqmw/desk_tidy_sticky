# 2026-02-08 Sticky 磨砂效果控制（与透明度并列）

## 目标
当桌面颜色与贴纸文字接近时，提高可读性；新增“磨砂强度”可调控件，交互与透明度一致。

## 功能设计
1. 新增 `frost` 持久化字段（0 ~ 1），用于控制磨砂强度。  
2. 透明度与磨砂都具备默认值：
   - `opacity` 默认 `1.0`
   - `frost` 默认 `0.22`
3. UI 放在透明度按钮旁边，支持：
   - 点击展开滑条
   - 鼠标悬浮图标直接滚轮微调
   - 实时百分比反馈

- `src-tauri/src/notes.rs`

  - 新建便笺默认写入 `opacity`/`frost` 默认值

  - 新增 `update_note_frost(...)`
- `src-tauri/src/lib.rs`

    - 覆盖层 `::before` 叠加轻度亮化，提升文字对比度

## 2026-04-15 补充：贴纸主壳改为真正的毛玻璃表面

### 背景
- 原实现把贴纸底色直接写成 `rgba(noteColor, opacity)`。
- 这会导致两个问题：
  - `透明度=100%` 时实际更接近不透明，和用户对“透明度”的直觉相反。
  - `frost` 虽然有 blur，但如果表面 tint 太实，磨砂感会被盖掉，导致调节看起来不明显。

### 本次收敛
1. 保留原贴纸的轻量基调，不引入厚重玻璃卡片外壳。
2. `透明度` 重新映射为贴纸表面 alpha：
   - `100%` = 完全不透明
   - `0%` = 完全透明
3. `frost` 继续独立控制两层效果：
   - 优先使用原生窗口材质（macOS vibrancy / Windows blur）
   - 网页层背景磨砂作为 fallback
   - 背景磨砂层的白雾遮罩强度
4. 这样两个控件都能保持可感知变化，而且不会破坏之前的贴纸质感。
5. 磨砂层必须位于正文内容层之后，不能直接作用到贴纸自己的文字、按钮和编辑器。
6. 贴纸 tint 与 `backdrop-filter` 需要挂在同一个稳定背景层上，避免只在滚动重绘时短暂出现磨砂。
7. 贴纸窗口创建后与贴纸页挂载后都需要重试应用原生窗口效果，避免底层句柄稍晚可用时漏掉材质。
8. 贴纸窗口创建时应显式使用透明背景色，确保原生材质不会被 webview 默认底色盖住。
9. 即使原生材质已成功应用，网页层也保留一层弱 blur 作为稳定 fallback，不直接归零。
10. 原生材质的真正生效链路应由后端统一负责，不能继续依赖前端页面直接调用 `window.setEffects(...)`。
11. 每次贴纸创建、恢复显示、层级同步、全局操作切换后，都需要重新补挂一次原生磨砂，避免 Win/mac 在重排窗口层级后丢失材质。
12. 前端磨砂层、正文层与底部遮罩必须共用同一套圆角裁剪边界，避免透明 / 毛玻璃启用后在底角露出矩形合成块。
13. 贴纸主壳本身也必须执行窗口级圆角裁切；仅裁正文层不足以消除透明窗口壳残留。

### 回归点
1. `透明度=100%` 时，贴纸背景应完全不透明。
2. `透明度=0%` 时，贴纸背景应完全透明。
3. `磨砂` 调高时，贴纸后方的其他 app / 桌面内容应稳定持续模糊，不能只在滚动时短暂出现。
4. 默认贴纸仍保持之前较轻的便签气质，不变成厚重玻璃卡片。
5. 贴纸自己的正文、标签、工具栏始终保持清晰，不能被磨砂层一起模糊。
6. Win 上 `磨砂 > 0` 时不能再出现“完全直透”；mac 上静止不滚动时也必须保持模糊。
7. 贴纸底部左右圆角在静止、悬浮、编辑态下都应保持完整，不能出现方角透明块。
