# 2026-02-08 Sticky 底部工具栏悬浮遮罩交互

## 目标
默认显示更多正文内容；鼠标悬浮时再显示底部工具栏，并用遮罩降低底部文字干扰。

## 调整
- 文件：`src/routes/note/[id]/+page.svelte`
- 变更：
  1. 工具栏改为绝对定位覆盖层，不再占用正文布局高度。  
  2. 新增 `toolbar-mask`（底部渐变遮罩），仅在悬浮时显示，并提高遮挡强度。  
  3. 工具栏增加半透明底板、描边、阴影与轻微模糊，避免底层文字干扰图标可读性。  
  4. 悬浮时工具栏淡入并启用点击；非悬浮状态下工具栏隐藏且不接收指针事件。

## 结果
1. 非悬浮状态下底部区域可继续显示文本内容。  
2. 悬浮后底部文字会被明显遮挡，工具栏按钮不再受正文视觉干扰。

## 2026-04-16 补充：底部遮罩与贴纸圆角裁剪同步

### 背景
- 在贴纸开启透明 / 磨砂后，底部工具栏遮罩仍按矩形铺底。
- 悬浮或操控态下，左右下角会露出“方形透明块”，视觉上像贴纸圆角被切坏。
- 该问题在 macOS 与 Windows 都会出现，只是合成表现略有差异。

### 调整
1. `toolbar-mask` 不再从 `0/0/0` 直接铺满到底部，而是收紧到贴纸 client 区内侧。
2. `toolbar-mask` 的底部圆角改为跟随贴纸主半径，避免遮罩自身把底角切成方形。
3. 贴纸正文容器补齐 `border-radius + overflow: hidden`，确保底部遮罩、正文层与磨砂层走同一套裁剪边界。
4. 贴纸主壳增加窗口级 `clip-path` 圆角裁切，外阴影改为跟随形状的 `drop-shadow`，不再让矩形窗口壳残留在圆角外。

### 回归点
1. 悬浮显示工具栏时，左右下角不应再出现方形透明块。
2. 编辑态 / 操控态下，底部遮罩过渡仍应保留，但只能沿贴纸圆角收口。
3. macOS 与 Windows 下，贴纸边缘都不应再露出矩形合成边。

## 2026-04-16 补充：置顶贴纸操控态改为底部外置工具栏

### 背景
- 置顶贴纸双击进入操控态后，底部按钮直接压在正文上，长内容会被明显遮挡。
- 顶部标签区当前设计较稳定，不需要一起挪动。

### 调整
1. 普通贴纸继续保留原来的贴纸内 hover 工具栏。
2. 置顶贴纸进入操控态后，底部工具栏改为贴纸主体外侧的独立一行，并按工具栏高度临时拉高窗口，不再覆盖正文，也不挤压正文区。
3. 顶部标签区保持在贴纸内部，只保留现有的优先级 / 标签编辑布局。

### 回归点
1. 双击置顶贴纸进入操控态后，正文区域不应再被底部按钮遮挡。
2. 置顶贴纸在非编辑态下仍应保持可拖动，不能因为底部工具栏外置而把拖拽命中区缩回正文内部。
3. 非置顶贴纸的 hover 工具栏行为保持不变。
4. 顶部标签区布局和交互保持原样，不应因为底部工具栏外置而错位。

## 2026-04-16 补充：贴纸窗口尺寸持久化

### 背景
- 贴纸位置已经会在拖拽结束后写回，但宽高此前没有独立持久化命令。
- 结果是：关闭后重新打开，位置能恢复，尺寸却会回到旧值或默认值。
- 同时，置顶贴纸操控态会因为外置工具栏临时把窗口高度撑大，这一段高度不应该被误存成真实贴纸高度。

### 调整
1. Tauri 新增 `update_note_size` 命令，专门持久化贴纸逻辑尺寸。
2. 贴纸窗口页在 resize 时做低频保存，避免拖拽拉伸时高频写盘。
3. 关闭窗口前会强制 flush 一次，并同步触发 `notes_changed`，保证“最近关闭时状态”不仅落库，也能刷新主面板内存态。
4. 当置顶贴纸显示外置工具栏时，持久化高度会自动扣除工具栏预留区，只保存用户真实贴纸高度。
5. 对“取消钉住 / 归档 / 删除”这类会立刻关闭贴纸窗口的动作，会先强制保存当前尺寸，再执行业务命令，避免响应里带回旧宽高。
6. 尺寸保存优先读取 Tauri 原生窗口 `innerSize + scaleFactor` 转出的逻辑尺寸，不再依赖 DOM `window.innerWidth / innerHeight`，以覆盖 Windows 上 WebView 尺寸同步不稳定的情况。
7. 贴纸窗口增加低频尺寸轮询与失焦保存兜底，确保 Windows 下即使 `resize/close` 事件偶发丢失，也能在短时间内落库最近尺寸。
8. 主面板在关闭任意贴纸窗口前，会通过后端命令直接读取该窗口原生尺寸并持久化，作为“关窗前最后一次兜底”，避免依赖单一前端事件。

### 回归点
1. 用户手动调整贴纸长宽后，关闭再开启，应恢复为最近一次关闭时的尺寸。
2. 仅进入操控态导致的临时窗口增高，不应污染贴纸真实高度。
3. 位置持久化行为保持原样，不应因为尺寸保存新增而回归。

## 2026-04-16 补充：桌面贴纸显隐开关与窗口同步并发收敛

### 背景
- 桌面贴纸开关在某些时序下会“关闭无效”，表现为点击关闭后贴纸仍保持开启。
- 根因是窗口同步使用单次互斥：同步进行中再次触发会直接等待并返回，导致“最后一次状态”没有被再次执行。

### 调整
1. `createWindowSync` 的 `syncWindows()` 改为“请求合并 + 串行收敛”模式。
2. 同步进行中收到新请求时仅标记 `syncRequested=true`，当前轮结束后会继续按最新状态再跑一轮，直到无新请求为止。
3. 保持现有开关语义不变：`overlayEnabled=false` 时强制关闭全部 `note-*` 窗口；`true` 时按已钉住状态恢复。
4. 所有面板窗口都接入 `preferences_changed.overlayEnabled` 同步；任一窗口切换贴纸开关后，其余仍在后台存活的窗口也会立即更新本地 `stickiesVisible` 并执行一次窗口同步，避免旧窗口按过期状态重开贴纸。

### 回归点
1. 连续快速点击“桌面贴纸开关”后，最终状态必须与最后一次点击一致。
2. 在 `notes_changed` 高频触发场景下，关闭贴纸后不应被旧同步流程自动拉起。

## 2026-04-16 补充：Windows 首次开启贴纸闪动优化

### 背景
- Windows 上刚开启桌面贴纸时，贴纸会出现数次明显闪动；macOS 不受影响。
- 根因是首次创建贴纸窗口时，前端会显式 `window.show()`，而 Windows 的 WorkerW/桌面层挂载流程又额外通过 `SetWindowPos(... SWP_SHOWWINDOW ...)` 触发可见刷新，导致一次开启里出现多次 show。

### 调整
1. Windows WorkerW 挂层、壁纸层挂层、置底刷新和 detach 后恢复顶层的 `SetWindowPos` 全部移除 `SWP_SHOWWINDOW`。
2. 层级修正现在只负责“改父级 / 改 Z 序 / 刷 style”，首次真正让贴纸变可见的动作统一交给前端显式 `window.show()`。
3. 新建贴纸窗口改为隐藏创建后等待 note 页面发出 `note_window_ready`，确认数据、交互策略与层级初始化完成后再执行唯一一次 `window.show()`。
4. 首次显示后不再执行额外的 layer retry；恢复已存在的隐藏窗口时也只做一次 show 前层级准备，避免 Windows 多次刷新窗口造成闪动。

### 回归点
1. Windows 开启桌面贴纸后，贴纸首次出现应明显减少闪动。
2. 贴纸在置顶、置底、贴壁纸层三种状态间切换时，层级行为不能回归。

## 2026-04-16 补充：Windows 贴纸批量开启/关闭耗时收敛

### 背景
- 为减少 Windows 首次开启闪动，贴纸窗口改为等待 `note_window_ready` 后再显示。
- 如果多个贴纸逐个串行等待 ready/timeout，Windows 上开启和关闭都会明显变慢，且重复同步时可能出现“启动不全面”的感知。

### 调整
1. `createWindowSync` 增加有界并发窗口任务执行，批量开启、关闭、恢复都按最多 4 个窗口并发推进。
2. `creatingLabels` 从 `Set` 改为 `Map<label, Promise>`，重复同步遇到正在创建的贴纸会等待同一个创建任务，而不是直接跳过。
3. 关闭隐藏贴纸和清理失效贴纸时，也改为并发持久化尺寸并关闭窗口，避免逐个等待。

### 回归点
1. Windows 上开启/关闭多个桌面贴纸的耗时应明显下降。
2. 快速切换贴纸开关或触发多次同步时，最终打开的贴纸数量应与已钉住且未归档/未删除的列表一致。
