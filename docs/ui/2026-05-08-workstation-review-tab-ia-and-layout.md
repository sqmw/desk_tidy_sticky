# 工作台 回顾 Tab 界面与布局蓝图（2026-05-08）

## 1. 目标

为 `workstation（工作台）` 的新一级 tab `回顾` 定义一套足够稳定的界面结构，保证后续实现时：

1. 不和 `笔记`、`专注` 打架
2. 不把“记录、日历、统计”揉成一个杂糅页面
3. 可以逐阶段实现，而不用一次性做完全部能力

---

## 2. 一级与二级结构

## 一级 tab

- 笔记
- 专注
- 回顾

## 回顾 tab 的二级结构

- 记录
- 日历
- 统计

推荐默认落点：

- `记录`

原因：

1. 用户进入回顾页时，最想知道的是“我做了什么”
2. `记录` 比 `统计` 更有人味，也更像主场
3. `统计` 放第三位，不会把整个页面导向“纯数字分析工具”

---

## 3. 页面总布局

推荐沿用当前 workstation 的双栏心智，但回顾页比笔记页更偏“主内容区 + 右侧详情”。

## 布局草图

```text
+--------------------------------------------------------------+
| 顶部摘要条：今日专注 / 今日已办 / 本周已办 / 连续记录        |
+--------------------------------------------------------------+
| 二级切换：记录 | 日历 | 统计                                 |
+------------------------------------------+-------------------+
| 主内容区                                  | 右侧详情区        |
|                                          |                   |
| 记录：时间线列表                          | 当前记录详情      |
| 日历：月历 + 日期聚合                     | 当天记录详情      |
| 统计：图表/时间线/rollups                 | 统计说明或空态    |
|                                          |                   |
+------------------------------------------+-------------------+
```

### 主内容区

负责浏览。

### 右侧详情区

负责解释当前选中对象：

- 记录模式：当前记录详情
- 日历模式：当前日期详情
- 统计模式：某张统计卡的口径说明 / drilldown

这样做的好处是：

1. 和当前 `笔记` 页 inspector 心智一致
2. 不需要每点一下都整页跳转
3. 后续可以复用已有右侧详情布局经验

---

## 4. 顶部摘要条

## 作用

让 `回顾` 一打开就有内容，不会显得像一个空功能壳。

## 建议字段

1. 今日专注：`120m`
2. 今日已办：`3`
3. 本周已办：`12`
4. 连续记录：`5d`

### 不建议在这里放太多

不要一上来塞：

- 最佳日
- 周平均
- 月增长率
- 排名
- 完成率

原因：

1. 这会让顶部过重
2. 这些更适合放进 `统计`

---

## 5. 记录视图

## 5.1 主内容区

采用时间线或按日分组列表。

推荐第一版：

- 按天分组
- 每天下面按时间倒序展示记录

### 每条记录卡片建议字段

1. 标题
2. 完成时间
3. 一段摘要
4. 标签
5. 封面图缩略图（可选）

### 样式建议

不要做成当前 mini 列表那种“功能按钮很多的管理卡”，而应更像“完成日志卡”：

- 信息优先
- 操作收敛
- 编辑、删除等动作弱化

## 5.2 右侧详情区

显示当前选中记录：

1. 标题
2. 完成时间
3. 完整正文
4. 图片
5. 标签
6. 来源（手动 / 来自专注任务）

### 创建入口建议

不要把“新建已办记录”藏太深。

建议两种入口：

1. 顶部按钮：
   - `记录已办`
2. 空态时主按钮：
   - `写下今天完成了什么`

---

## 6. 日历视图

## 6.1 主内容区

第一版建议只做：

- 月历

### 日期格子里显示什么

1. 当天记录数
2. 1 个缩略封面或 1~2 条标题摘要

### 视觉语义

- 无记录：干净浅底
- 有记录：轻高亮
- 记录多：数量角标
- 当前日期：明显但不过重

## 6.2 右侧详情区

当用户点某一天时，右侧显示：

1. 日期标题
2. 当天总记录数
3. 当天所有记录列表
4. 点击其中一条可继续展开完整内容

### 为什么不建议用弹窗

因为工作台本身就是高信息密度环境，右侧详情比 modal 更适合连续浏览。

---

## 7. 统计视图

## 7.1 定位

`统计` 是 `回顾` 的一个子视图，不再是 `专注` 的附属折叠区。

它负责回答：

1. 最近做成了多少
2. 专注时间和产出是否匹配
3. 哪些任务 / 类型最常出现

## 7.2 第一版建议承接现有专注统计

先把已有能力搬过来：

1. 今日专注分钟
2. 今日番茄总数
3. 最近 7 天趋势
4. 连续专注天数
5. 最佳专注日
6. 热力图
7. 今日任务分布时间线
8. 任务 rollups

### 然后逐步新增“已办相关统计”

第二步再加：

1. 今日已办数
2. 本周已办数
3. 已办类型分布
4. 专注时长 vs 已办数量

这样迁移风险最小。

### 2026-05-08 当前状态补充

- `回顾 -> 统计` 已经开始承接真实专注统计内容。
- `专注` 页已不再显示原先的完整折叠统计面板，而是改成轻量摘要卡 + `打开回顾` 入口。
- 当前 `记录 / 日历` 仍处于骨架阶段，因此 `回顾` 页现在是“统计先落地，记录/日历后续接入”的节奏。

## 7.3 右侧详情区

统计页右侧不一定要放记录详情，更适合放：

1. 当前图表口径说明
2. 当前选中维度的说明
3. 一个轻量 drilldown 区

例如：

- “今日已办数：按 `completed_at` 所在自然日统计”
- “番茄数：统计已完成的 focus session”

---

## 8. 与当前页面的职责切分

## 笔记页保留

- 普通 note 的创建与编辑
- 标签整理
- 活动/归档/回收站

## 专注页保留

- 任务规划
- 运行态番茄
- 休息控制
- 少量 summary

## 回顾页承担

- 已办记录
- 日历回看
- 完整统计

这是最关键的职责边界。

---

## 9. 第一版空态设计

## 记录空态

文案建议：

- `今天还没有已办记录`
- `记下一件你刚完成的事，回头看会很有成就感`

按钮：

- `记录已办`

## 日历空态

文案建议：

- `这个月还没有已办记录`
- `开始记录后，这里会慢慢长出你的完成轨迹`

## 统计空态

文案建议：

- `数据还不够生成完整回顾`
- `先记录几天，我们再一起看趋势`

## 10. 第一版实现建议

## 10.1 组件层级

建议新增：

- `WorkspaceReviewHub.svelte`
  - 回顾页总容器
- `WorkspaceReviewSummaryBar.svelte`
  - 顶部摘要条
- `WorkspaceReviewTabs.svelte`
  - 二级 `记录 / 日历 / 统计`
- `WorkspaceReviewLogList.svelte`
  - 记录列表
- `WorkspaceReviewCalendar.svelte`
  - 月历
- `WorkspaceReviewStats.svelte`
  - 统计页封装
- `WorkspaceReviewInspector.svelte`
  - 右侧详情区

## 10.2 状态建议

回顾页自己维护：

- `reviewSubtab`
- `selectedLogId`
- `selectedReviewDate`
- `selectedStatsPanel`

不要继续把这些状态塞进 `WorkspaceFocusHub` 内部。

---

## 11. 不建议的实现方式

1. 不要把 `记录 / 日历 / 统计` 全堆在同一个长页面里
2. 不要把 `统计` 继续只是 `专注` 页底部折叠区
3. 不要让 `已办记录` 看起来像 mini 笔记列表的复制品
4. 不要让 `回顾` 页同时承担编辑器和运行控制

---

## 12. 最终建议

`回顾` 页的最佳形态不是“多一个页面”，而是：

> 让 workstation 终于拥有一个明确的结果层。

所以布局原则应该是：

1. 顶部先给出 summary
2. 中间用二级视图切换承接三种浏览任务
3. 右侧详情保持高信息密度但不打断浏览
4. 让 `记录` 成为主角，`统计` 成为辅助解释层
